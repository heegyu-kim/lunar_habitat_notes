# Sticky Notes for Lunar Habitat VR. Design Notes

## 1. 왜 스티키 노트인가

Lunar habitat을 설계할 때 엔지니어와 건축가는 같은 공간을 놓고 다른 언어로 말한다.
엔지니어는 "이 벽 뒤에 배관이 지나가서 못 옮긴다"(제약)를,
건축가는 "여기 창을 내면 심리적으로 훨씬 낫다"(제안)를,
거주자는 "자고 일어나면 이 랙 모서리에 머리를 부딪친다"(관찰)를 말한다.

도면이나 회의록에서는 이 세 목소리가 섞여서 사라진다.
VR 디지털 트윈 안에서 **그 자리에 그 사람의 말을 그대로 붙여 두면**
의견은 공간에 남고, 다른 사람이 같은 자리에 서서 그 말을 다시 들을 수 있다.

이 도구는 Design → Experience → Reflect → Redesign 루프의 Reflect 단계를 담당한다.
무엇을 하라고 강제하지 않고 "여기에 할 말이 있으면 붙여라"만 제공하는 디자인 프로브다.

## 2. 노트 한 장이 반드시 가지는 네 가지

| 축 | 필드 | 설명 |
|---|---|---|
| 누가 | `author`, `role` | 역할은 Engineer / Architect / Inhabitant. 세션 시작 때 명함 카드에서 한 번 정하면 모든 노트에 찍힌다 |
| 어디 | `position`, `normal`, `anchor_name`, `camera_position`, `camera_rotation` | 붙은 좌표와 표면 방향, 붙은 부재 이름, 그리고 **작성자가 서 있던 자리와 시선**. "Go there"와 투어가 이 시점으로 돌아간다 |
| 무엇 | `type`, `text`, `resolved` | 유형 다섯 가지. 색으로 바로 구분된다 |
| 어떻게 | `screenshot_file`, `audio_file`, (예정) sketch, motion, alternative | 글로 못 쓰는 의견을 남기는 매체들 |

### 유형과 색

| 유형 | 색 | 누가 주로 쓰나 (기본값) | 예 |
|---|---|---|---|
| Constraint | 빨강 | Engineer | 이 패널 뒤로 ECLSS 덕트가 지나감. 이동 불가 |
| Requirement | 주황 | | 비상 해치까지 접근 경로 폭 0.8m 이상 확보 |
| Proposal | 파랑 | Architect | 수면 포드를 해치 반대편으로 돌리면 어떨까 |
| Question | 보라 | | 이 랙 위 공간은 비워 두는 이유가 있나 |
| Observation | 초록 | Inhabitant | 여기 서면 천장이 낮게 느껴진다 |

새 노트의 유형은 내 역할의 기본값으로 시작하고, 작성 창에서 바꿀 수 있다.

### 답글, 상태, 충돌

- 노트에 노트가 달린다 (`parent_id`). 패널에서 채팅처럼 아래로 쌓이고, 입력창에 적고 Enter면 바로 붙는다. 답글도 유형과 음성을 가진다.
- `resolved`는 Open / Resolved. 해결된 노트는 회색으로 흐려지되 지우지 않는다. 왜 그렇게 설계됐는지가 기록으로 남아야 하기 때문이다.
- **충돌.** 같은 부재(`anchor_name`)에 열린 Constraint와 Proposal이 함께 붙어 있으면 그 부재의 핀들이 느리게 숨쉰다. 목록 제목줄과 리포트 맨 위에도 충돌 부재가 적힌다. "여기서 엔지니어와 건축가 의견이 갈린다"를 공간이 먼저 알려주는 장치이며, 이 프로젝트가 조율 도구라는 걸 보여주는 유일한 시각 신호다.

## 3. UI / UX 원칙

### 공간을 가리지 않는다
모달 창이 없다. 오른쪽 380px 사이드 패널 하나가 Note / List / Session 세 탭을 담당하고, 3D 뷰는 그대로 보인다.
패널이 열리면 마우스만 풀리고, 오른쪽 버튼 드래그로 둘러볼 수 있다.
패널에서 보고 있는 노트는 월드에서 1.35배로 커지고 카드가 펼쳐진 채 유지된다.

### 노트는 두 단계로 보인다
- **멀리서** 지름 9cm 구슬(핀). 유형 색, 역할 머리글자(E / A / I). 답글 수는 아래 작은 숫자. 해결되면 회색 반투명.
- **가까이 (3m 안), 조준 중, 또는 패널에서 보는 중** 핀 위로 카드가 펼쳐진다. 유형, 본문 두 줄, 작성자, 시간.

구슬은 어느 각도에서나 같게 보이고 글자는 빌보드라 뒤에서도 읽힌다. 카드만 표면과 평행하게 선다.

### 색은 정보다
UI는 거의 무채색(짙은 회색 반투명, 흰 글자). 색은 유형 다섯 가지에만 쓴다.
화면 오른쪽 위 칩 다섯 개가 유형별 개수를 보여주고, 클릭이나 1~5 키로 그 유형을 월드에서 숨기거나 보인다.
"엔지니어 제약만 보고 싶다"는 나머지 네 개를 끄면 된다.

### 배치는 미리 보고 확정한다
N을 **누르고 있는 동안** 반투명 핀이 조준점 자리의 표면을 따라다니고, 떼는 순간 그 자리에 붙는다.
붙는 순간 HUD를 숨기고 스크린샷을 찍어서 노트에 첨부한다.

### 리뷰 미팅을 위한 투어
List 탭의 Tour 버튼은 필터된 노트를 순서대로 돈다. `]` 다음, `[` 이전, Esc 종료.
각 노트의 작성자 시점으로 이동하고 패널에 그 노트가 열린다. "첫 번째 의견부터 봅시다"가 버튼 하나로 된다.

## 4. 범위

### 현재 레포
1. 명함 카드 (이름·역할 한 번 입력, Session 탭에서 변경)
2. N 홀드 배치 미리보기 + 자동 스크린샷
3. 사이드 패널 작성 창 (유형 버튼, 텍스트, 음성 녹음)
4. 두 단계 3D 핀, 조준·포커스 강조, 충돌 펄스
5. 대화형 답글 (텍스트·음성·유형), Resolve, Delete
6. 유형 표시/숨김 칩 (클릭, 1~5 키)
7. 목록 필터, Go there, 투어 모드
8. 세션 JSON 저장/불러오기 (전송 1단계)
9. HTML 리뷰 리포트 내보내기 (이미지·음성 포함 단일 파일, 부재별 묶음, 충돌 표시)

### 다음 단계 (스키마에 자리만 열어 둠)

| 기능 | 뭘 남기나 | 왜 필요한가 |
|---|---|---|
| V 홀드 빠른 음성 노트 | 패널 없이 보면서 말하고 떼면 저장 | VR에서 가장 자연스러운 입력 |
| 3D 스케치 | 컨트롤러로 공중에 그은 선 (점 배열) | "이 정도 크기로 여기에" 같은 형태 의견 |
| 동작 기록 | 몇 초간의 머리·손 궤적. 고스트로 재생 | "여기서 저 랙에 손이 안 닿는다"를 몸으로 보여줌 |
| 대안 배치 | 오브젝트 하나를 옮겨 둔 위치. 반투명 고스트 | "이렇게 옮기면?"을 원본은 두고 보여줌 |
| 네트워크 동기화 | 세션을 실시간으로 공유 | 파일 주고받기 대신 같은 공간에 동시에 |
| XR 입력 | 컨트롤러 광선으로 배치, 손목 패널 | 데스크톱 입력을 `note_placer.gd`에서만 갈라 두었으므로 이 파일만 바꾼다 |

## 5. 데이터 스키마 (session json)

```json
{
  "format": "sticky_notes",
  "version": 1,
  "saved_at": "2026-10-24 17:30:00",
  "notes": [
    {
      "id": "1761341400_0427",
      "parent_id": "",
      "author": "Daniel",
      "role": 1,
      "type": 2,
      "text": "Rotate the sleep pod so the head faces away from the hatch.",
      "resolved": false,
      "position": [2.8, 0.7, 2.35],
      "normal": [0.0, 1.0, 0.0],
      "anchor_name": "SleepPod",
      "camera_position": [1.9, 1.65, 1.2],
      "camera_rotation": [-0.4, 0.6, 0.0],
      "screenshot_file": "shot_1761341400_0427.png",
      "audio_file": "voice_1761341400_0427.wav",
      "created_at": "2026-10-24 17:30:00"
    }
  ]
}
```

`role`과 `type`은 정수 enum. 순서는 `note_data.gd`의 `TYPE_NAMES`, `ROLE_NAMES`와 같다.
미디어는 파일 이름만 저장하고 항상 `user://sticky_notes/media/` 아래에서 찾는다.
세션 json과 media 폴더를 함께 옮기면 어느 컴퓨터에서든 열린다. 리포트 HTML은 미디어를 안에 품고 있어서 파일 하나로 끝난다.

## 6. 구조

```
addons/sticky_notes/
  note_data.gd          데이터 한 장 (직렬화, 역할별 기본 유형)
  note_manager.gd       Autoload. CRUD·저장·불러오기·스크린샷·녹음·표시/숨김·충돌·리포트·텔레포트 신호
  note_placer.gd        카메라에 붙이는 입력 도구. 홀드 배치, 조준, 투어. HUD·패널·명함을 만든다
  note_report.gd        HTML 리포트 생성
  sticky_note.gd        월드의 핀 + 카드 (코드로만 생성)
  ui/
    note_ui_kit.gd      색·스타일 토큰, 공통 빌더, ChoiceRow
    note_hud.gd         나, 유형 칩, 조준점, 투어 상태, 키 안내
    note_panel.gd       사이드 패널 (Note / List / Session)
    identity_card.gd    시작 명함
demo/
  demo.tscn, player.gd  테스트용 방과 1인칭 플레이어
```

설계 원칙 세 가지.

- **데이터와 표현 분리.** `NoteData`는 Godot 노드가 아니다. JSON으로 바로 나가고, 네트워크로 보낼 때도 그대로 쓴다.
- **입력은 한 파일에.** 데스크톱 전용 코드는 `note_placer.gd`와 `demo/player.gd`에만 있다.
- **씬 파일 없음.** 애드온 안의 모든 UI와 3D 노트는 코드로 만든다. 폴더 하나 복사하면 끝난다.
